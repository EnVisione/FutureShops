## Delivered contract

Diagnostics now emit schema version 2 and keep capability evidence in separate fields. Every enabled provider or transaction event records `required_capabilities`, `provider_declared_capabilities`, and `account_observed_capabilities`. The legacy `observed_capabilities` field remains as an alias for wire compatibility. The additive provider overload accepts the declared and observed sets independently, so a provider declaration cannot be mistaken for account proof.

The Pixelmon provider now records balance and precheck evidence from the actual account object. Native receipt accounts expose the mutation, lookup, and retry observations. Custom or hybrid wrappers expose only the query and precheck observations, even when the native mixin class is present. This makes the reported all true capability mismatch visible and keeps the mutation refusal before journal or custody effects.

The capture is default off and bounded to 60 seconds, 100 events per second, 2,000 events, 5 MiB per capture, and 4 KiB per event. Status reports the capture ID, module, remaining time, event count, dropped event count, byte counter, limits, and server log output. Rate and size overflow drops diagnostic events only and cannot block or mutate an economy operation. Timeout and reset clear the session and counters. Existing command syntax and operator permission are unchanged.

`docs/economy-debugging.md` documents the command, console procedure, exact fields, privacy redaction, account verdict rules, and recovery procedure. The public API guide and documentation index link the new contract and task receipts.

## Boundaries and open gates

The current command still enables one module at a time and does not add an unbounded target selector. Account and request filtering remains optional follow up work if the exact runtime procedure requires it. Diagnostic fields are not authority, receipts, or balance evidence. `account_observed_capabilities` is only populated by an adapter that supplies independent runtime proof; missing proof remains a refusal reason.

The reported Mohist `custom_or_hybrid` transaction therefore remains safely refused until the account binding, exact writer inventory, and durable same image receipt protocol pass. This task does not enable a Pixelmon hybrid mutation path or make a 2.4.1 release claim.
