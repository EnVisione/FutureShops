## Direct route result

`direct_exact_reflection_v1` is disqualified by the following exact observations.

1. `FEBankAccount.take` and `add` call `FEPlayerData.removeMoney` and `addMoney` and return only a boolean. The call has no FutureShops request UUID or durable receipt.
2. `FEPlayerData.getMoneyWrapper` returns a mutable `NumberWrapper<Double>`. Direct `setValue`, `increment`, and `decrement` can bypass a lock placed around the named bank methods.
3. `FEPlayerData.setRecentChanged` constructs and dispatches `EconomyUpdateEvent`. Listener reads, mutation, and reentry are not covered by a FutureShops-only Config lock.
4. `PlayerData.savePlayerData` and `forceSavePlayerData` submit `Config.saveAsync`. A successful queue submission is not a durable acknowledgement and a stale queued save can publish an older image.
5. `Config.save`, `save(File)`, `saveAsync`, and `reload` share backend locking that is not a proof that the FutureShops receipt and the external balance commit one image together.
6. `FEBankAccount.getBalance` can floor through `PEBSettings.removeDecimals`. A displayed balance is not sufficient proof of the raw authoritative value.
7. The exact runtime log identifies an isolated plugin class loader. Static class names and a native Pixelmon mixin do not prove that the external `FEPlayerData` writer image is interposed by the FutureShops transformer.

These are route disqualifiers, not permission to fall back to the internal ledger, a balance mirror, a sidecar receipt, or a boolean mutation result.

## Required stronger route

Phase 005 may proceed only after a separately installed transaction-aware route or an original FutureShops adapter interposes every writer in the exact `FEPlayerData` image. The route must persist one namespaced immutable receipt beside the raw balance, carry the request, actor, account, backend lineage, currency, operation, amount, before and after values, image revision, fingerprint, and checksum, and acknowledge only after force, replacement, and readback succeed. It must also expose lookup and deduplicated retry after a fresh process.

The route must be proved for mutable wrapper aliases, all bank methods, economy event listeners, asynchronous and scheduled saves, dirty flags, Config reload, shutdown, cache aliases, path and file faults, queue limits, duplicate and conflicting UUIDs, and every injected crash stage. Unknown or contradictory records must enter `RECOVERING` or `FROZEN` without guessing the external effect.
