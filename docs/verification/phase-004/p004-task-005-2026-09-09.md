## Direct route result

`direct_exact_reflection_v1` remains disqualified. Exact bytecode inspection and the task 004 inventory show that `take` and `add` return booleans without request identity, `getMoneyWrapper` exposes mutable `NumberWrapper<Double>` writers, `setRecentChanged` dispatches a synchronous economy event, `saveAsync` acknowledges only queue submission, reload and save references are not covered by a FutureShops lock, and the display path can floor raw money. The native FutureShops mixin also cannot transform the Bukkit account class in the isolated plugin class loader. These findings require the stronger route and do not permit internal fallback or a sidecar authority.

## Stronger route invariants

The bridge admits only the exact `FEBankAccount` class and verifies FinalEconomy `1.0.9`, EverNifeCore `2.0.4.4`, PixelmonEconomyBridge `1.1.6`, and Vault `1.7.3`. It resolves the private `FEPlayerData` identity and installs one receipt aware wrapper for every observed `NumberWrapper` mutator, including `setValue`, `increment`, `decrement`, `multiply`, `divide`, `boundLower`, `boundUpper`, `bound`, and `normalize`. The account `take`, `add`, and `setBalance` paths therefore use the same fair ledger lock. Reads, writer callbacks, receipt persistence, and the normal synchronous economy event remain serialized.

Every accepted mutation writes the raw balance and one immutable namespaced receipt to the same FinalEconomy PlayerData image. The receipt contains schema and protocol, request, root and leg IDs, actor and account identity, backend lineage, currency, operation, exact amount, before and after values, definitive result, image revision, request fingerprint, checksum, and external operation ID. Persistence writes a same filesystem temporary image, invokes the backend serializer, forces the temporary file, atomically replaces the target, forces the parent directory, reads the target back, and only then returns `CONFIRMED`.

Calls received off the Bukkit server thread are marshaled to the server thread before invoking `FEBankAccount`. This prevents asynchronous `EconomyUpdateEvent` failures and gives concurrent duplicate requests one ordered account image. Dispatch interruption and timeout are not confirmation. Missing, malformed, contradictory, or conflicting receipts return typed refusal or ambiguity and never use the internal wallet.
