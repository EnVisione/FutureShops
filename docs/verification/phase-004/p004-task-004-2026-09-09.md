## Numeric matrix

FutureShops uses signed integer minor units. The exact external route is safe only when the raw `double` round trip is exact and bounded.

| Input class | Expected admission |
| --- | --- |
| zero, negative, negative zero | reject before effect |
| positive integral values through `2^53 - 1` | candidate only after exact round trip and writer exclusion |
| `2^53`, `2^53 + 1`, and higher values | reject unless the exact raw representation and minor conversion are proven |
| fractional values | reject with `INVALID_PRECISION`, never floor or truncate |
| NaN and positive or negative infinity | reject with `INVALID_PRECISION` |
| long overflow after checked scaling | reject with `INVALID_PRECISION` or `INVALID_AMOUNT` before provider call |
| `PEBSettings.removeDecimals=true` | direct route disqualified because `getBalance` floors raw money |
| `PEBSettings.removeDecimals=false` with fractional raw money | direct route still disqualified until exact integer predicate and image proof pass |

## Decision

`EconomyAmounts.fromRawDouble` now supplies the reusable exactness predicate used by feasibility probes. It rejects non finite values, negative zero, fractions that do not match the configured precision, values above the exact double boundary, and checked conversion failures before any provider call. The focused numeric regression covers integral values through `2^53`, fractional input, NaN, infinities, negative zero, and the first unsafe representable value.

The focused numeric suite, full unit suite, and build passed on `node-1`.

```text
bash ./gradlew test --tests com.enviouse.futureshopsp.api.economy.EconomyAmountsTest --no-daemon
bash ./gradlew test --no-daemon
bash ./gradlew build --no-daemon
```

The full suite reported zero failures and zero errors. The build produced a local development jar only and did not change release metadata or publish an artifact.

The current source and bytecode evidence disqualify a direct reflective mutation route for production. The mutable wrapper, public wrapper accessor, Bukkit event reentrancy, asynchronous save path, and floor setting are not interposed by the existing FutureShops mixin. This is a disqualifying observation, not a refusal-only completion. `P004-TASK-005` must either prove a stronger exact route against the same `FEPlayerData` image or leave the production enablement gate open.

No custom or hybrid provider mutation was enabled. The reported Mohist `custom_or_hybrid` precheck remains safely refused until a stronger route supplies independent account proof and durable receipt semantics.
